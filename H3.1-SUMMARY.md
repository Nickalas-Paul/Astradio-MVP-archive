# H3.1 - Users Module TypeScript Migration

## North Star Preserved
**One deterministic, observable `/api/compose` pipeline** remains unchanged. This migration uses strangler pattern to maintain full backward compatibility.

## Migration Strategy
- **Strangler Pattern**: TypeScript version alongside existing JS, compiled to `dist/routes/`
- **Ambient Types**: Legacy modules fenced in `types/legacy.d.ts`
- **API Surface**: Identical to original `routes/users.js`
- **Runtime**: Only compiled JS served, no `.ts` imports at runtime

## Files Created/Modified
- `routes/users.ts` (new TypeScript version)
- `routes/tsconfig.json` (new compilation config)
- `types/legacy.d.ts` (ambient type declarations)
- `dist/routes/users.js` (compiled output)

## Type Safety Improvements
- **Interfaces**: `User`, `Profile`, `Track`, `PublicUser` with proper typing
- **Request/Response**: Typed Express handlers with proper error handling
- **Database**: Typed return values from `getRow`, `getRows`, `update`, `insert`
- **Validation**: Proper typing for express-validator middleware

## Legacy Module Fencing
- `../lib/authentication` - JWT and auth middleware
- `../lib/database` - Database query functions  
- `../lib/redis` - Redis client wrapper
- `../lib/storage` - S3 upload functions
- `multer` - File upload middleware
