# H3.2 - Library Module TypeScript Migration

## North Star Preserved
**One deterministic, observable `/api/compose` pipeline** remains unchanged. This migration uses strangler pattern to maintain full backward compatibility.

## Migration Strategy
- **Strangler Pattern**: TypeScript version alongside existing JS, compiled to `dist/routes/`
- **Ambient Types**: Legacy modules fenced in `types/legacy.d.ts`
- **API Surface**: Identical to original `routes/library.js`
- **Runtime**: Only compiled JS served, no `.ts` imports at runtime

## Files Created/Modified
- `routes/library.ts` (new TypeScript version)
- `dist/routes/library.js` (compiled output - 13,855 bytes)

## Type Safety Improvements
- **Interfaces**: `SavedTrack`, `LikedTrack`, `Playlist`, `PlaylistTrack`, `TrackPosition` with proper typing
- **Request/Response**: Typed Express handlers with proper error handling
- **Database**: Typed return values from `getRow`, `getRows`, `insert`, `update`, `remove`
- **Validation**: Proper typing for express-validator middleware

## Route Coverage
- `GET /library/saved` - User's saved tracks
- `GET /library/liked` - User's liked tracks
- `POST /library/playlists` - Create playlist
- `GET /library/playlists` - Get user's playlists
- `GET /library/playlists/:id` - Get playlist by ID
- `PATCH /library/playlists/:id` - Update playlist
- `DELETE /library/playlists/:id` - Delete playlist
- `POST /library/playlists/:id/items` - Add track to playlist
- `DELETE /library/playlists/:id/items/:trackId` - Remove track from playlist
- `PATCH /library/playlists/:id/reorder` - Reorder playlist tracks
